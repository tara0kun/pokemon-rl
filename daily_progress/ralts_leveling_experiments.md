# Raltsレベリング改善実験記録

## 目的
Raltsを効率的にLv16まで育てる方法を確立し、汎用レベリングシステムに統合する。

## 現状（実験前）
- Ralts Lv7-8で停滞
- SafeSwitch閾値`slot0 < 敵-1`でも経験値獲得が遅い
- 1勝あたり+10000+EXP獲得しているがLv9に上がる前にRalts自身が瀕死で停止

## 方式一覧

### 方式A: 弱敵限定戦闘 (実装中 - v10.9z80p)
- 条件: `enemy_lv <= 5` でRalts全戦闘、それ以外はBlaziken
- 期待: Raltsが安全に経験値獲得
- リスク: 強敵時にRaltsが参加すらしない=EXPゼロ
- **検証指標**: Raltsレベル変化、瀕死頻度

### 方式B: PassiveSwitch (1ターン参加)
- 条件: bcc=15まで待ってRalts攻撃→Blaziken交代
- 期待: 参加EXPで経験値分配
- リスク: 1ターン受けたダメージで瀕死

### 方式C: みねうち戦法
- 条件: Blazikenでみねうち→Raltsで弱攻撃
- 期待: 安全に最大EXP獲得
- リスク: みねうち未習得=実装不可

### 方式D: 経験値テーブル直接書き換え
- 条件: 仕様禁止（メモリ書き換え禁止）
- 不採用

## 効果測定方法
- 10分間隔でparty levels確認
- WIN/FIGHT/Encの推移
- Raltsの瀕死頻度

## 結果

### 方式A (敵Lv≤5限定): 失敗
- 20分間: WIN=26 / Ralts Lv8維持
- R116の野生はほぼLv6-9なのでRaltsが戦う機会ほぼゼロ
- 結果: 元のシステムと同じ＝Lv9に上がらず

### 方式A2 (敵Lv≤slot0_lv): 大失敗
- 20分間: WIN=8 (前回の1/3) / Ralts Lv8維持
- Raltsが頻繁戦闘→瀕死→PC回復で停滞時間激増
- FA問題誘発(8889/8890 OscTrap+FA)
- WIN効率が大幅低下

### 結論
Raltsで全戦闘はWIN効率が悪い。SafeSwitch早期交代の方が全体WIN数では優れる。

### 採用方針 (v80p3)
- 元の閾値`slot0 < 敵-1`に戻す
- slot0_heal機能(v80n)で瀕死即回復を維持
- Raltsは参加EXPでゆっくり育てる

### 将来検討
- みねうち戦法（Blaziken習得→交代）
- PassiveSwitch（bcc=15まで待ってRalts攻撃→交代）

### 汎用化
- レベリング設定はパーティメンバーごとに動的に判断すべき
- 現在のSafeSwitch閾値ロジックは健全
- Raltsだけ「Lv16到達まで参加EXPで成長」を許容する設計に統一
