### 1. 「気絶 deadlock」を architect が反証 (commit dfdc91bac)
- 私は「Sceptile 気絶 + Jagged Pass trainer で loop が freeze、自動回復不能」と判定し、user に

  enemy-faint 分岐が queue する pure `["B"]`。弱 mon が敵を KO しレベルアップ →「技を忘れる?
  YES/NO」⇄「習得やめる? YES/NO」を B が両方 NO で永久往復 (~1500 turn `battle_move:B@rem0`、
  cb2 は CB2_BattleMain 一定で ui_escape も gate で封じ)。
- **Fix1**: `["B"]`→`["B","B","A"]` (B,B が SHIFT NO + text 送り、trailing A が learn prompt YES
  = Rock Tomb 保護 or forget 画面 cb2 0x081BFAB5 で既存 ui_escape が decline)。
- **Fix2 (goals.py)**: field_heal_potion を `party0_hp > 0` で gate。気絶 lead は Potion 蘇生不能

- loop が gym の floor-hole パズルで 1F⇄B1F を ~70 turn oscillation。**私は「hole-aware BFS 未実装」

  architect に「regression/contamination の診断」として再フォーカス。
- **真因 (architect, ROM map data + ログ実測)**: 正しい nav model の上の **3 runtime 欠陥**:

  overworld bag は cb2=unknown_ui で ui_escape が処理、real START menu は白閾値で元々未検出)。
- **live 検証**: loop が **自律で hole chain を Flannery (13,9) まで踏破** (oscillation ゼロ)。

## 技術メモ (再利用可能)
- **gym floor-hole nav の脆さは runtime 欠陥 (level flicker / phantom menu / fallback gap) が
  正しい warp model を腐らせる形**。nav model 自体 (2311a677f) は正しかった。「振動 = model 欠如」
  と即断せず、まず flicker/phantom/contamination を疑え。
- **level flicker guard は badge-latch と同じ DMA-corruption family**。`party0_level < X` gate は
  全て lvl=0 misread で誤発火し得る → read root で guard するのが正解 (個々の gate でなく)。
- **Flannery (tid268)**: L24 Numel/L24 Slugma/L26 Camerupt/L29 Torkoal@WhiteHerb、全4体
  Overheat+Sunny Day。Torkoal は Def140 + Body Slam。Overheat は連用で SpAtk-2 累積 (White Herb
  で1回だけ復帰) → 弱 mon でも削り切れば Torkoal の Overheat は枯れる。**Water/Grass の Lombre が
  Fire 半減で Torkoal を安全に処理できる** (今回の勝因)。
