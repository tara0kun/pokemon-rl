## §31 Cycle 23: position-aware path_memory

### 実装 (path_memory.py 大幅改修)

#### 旧 schema
```json
{ "0-9": { "0-16": [["Up","Up","Up","Up","Up","Up","Up","Up"]] } }
```

#### 新 schema
```json
{
  "0-9": {
    "0-16": [{
      "from_pos": [11, 0],
      "to_pos": [11, 19],
      "seq": ["Up","Up","Up","Up","Up","Up","Up","Up"]
    }],
    "1-2": [{
      "from_pos": [14, 8],
      "to_pos": [2, 8],
      "seq": ["Up","Up","Up","Up","Up","Up","Up","Up"]
    }]
  }
}
```

同 `from_map → to_map` で `from_pos` が異なる record を **重複保存**。 Brain は
agent の cur_pos に Manhattan 距離 ≤5 の record のみ表示される。

#### 後方互換
旧 schema (list of seq) は `from_pos=None` の record として load。 distance
filter で自然に排除されるので新コードは旧 .json を読めるが旧 record は使われない。

#### nearby_records() API
新規メソッド: `(cur_g, cur_n, cur_x, cur_y, max_distance=5)` → `[(target_key,
record, distance), ...]` sorted by distance。

### v46 結果
- 134 pos / 5 maps / $1.50
- **(1, 3) 致命的 stuck 解消**: v44 1408 turn → 4 turn
- 0-9 から 1-2, 0-16, 1-4 を異なる from_pos で記録、 (5,5) と (7,8) と (12,7)
  でそれぞれ別の hint が出る (unit test 確認済)
- だが GOAL_DIRECTION が dead-end map (1, 3) を picks → 進歩方向選べず

### Mechanical success, statistical inconclusive
position-aware の効果は path_memory.json に直接観測可能、 (1, 3) 回避は v44 比較で明らか。 ただし coverage は v43 261 → v46 134 で regression。 GOAL_DIRECTION の選好ロジックが naive。

## §32 Cycle 24: onward-score weighting

### 動機
GOAL_DIRECTION が「visits 最少」 で選ぶと dead-end indoor (1, 3 は
1-2 にしか戻れない) が「未訪問だから魅力的」 と判定される。 本当に欲しいのは
「先に新しい場所へ進める map」。

### 実装
各 candidate target で `onward_score = self を除いた transition 数`:
- (1, 3) onward_score = 0 (1-2 にしか戻れない、 self loop)
- (0, 9) onward_score = 3+ (1-2, 1-4, 0-16, ...)

candidates ソートを `(-onward_score, t_visits, dist)` に変更 → dead-end 回避。

### v47 結果
- 204 pos / 4 maps / $1.50
- **GOAL_DIRECTION 0 fire** (max same_map_streak 74 < 100 閾値)
- onward_score 機構の本番 fire 観測できず = 検証 inconclusive
- 偶然 v43 と似た「自由探索」 状態で 204 pos = v43 261 にわずか劣る

- MapSurveyor の surveyed_this_session 解除条件 (例: tile_map のタイル数 <
  target/3 なら re-fire 許可)
- map 入場直後 K turn は「逆方向 (= 入った方向の逆)」 を強 bias

## §33 Cycle 25: BFS farthest on fresh map + Surveyor re-fire

### 動機
v43/v46/v47 共通: (0, 16) Route 101 = 21-24 turn しか滞在しない壁。 仮説:
南端から入場時 BFS prefer='nearest' が entry tile 近傍 = 南方向を picks。
'farthest' なら map 内陸 (北) を picks → 北進。

### 実装
1. `_call_brain`: tile_map for current map < 30 tiles → BFS prefer='farthest'
   default、 oscillating/suppress fallback で 'nearest' に swap
2. `MapSurveyor._should_start`: already_surveyed AND same_map_streak>=50
   AND tiles < target/3 → surveyed_this_session から除外し re-fire 許可

### v48 結果
- 202 pos / 5 maps / $1.50
- **(0, 16) Route 101 滞在 = 26 turn** (v47 24t、 v43 21t)
- noise 範囲内、 北進せず
- 同じ {Littleroot, Route 101, May 1F, May 2F, bedroom} cluster

### 教訓
Route 101 → Oldale の壁は BFS prefer の問題ではない。 おそらく構造的に:
- agent は南端から短時間しか滞在しない (戻る理由が強い)
- Brain visual signal で「北は遠い」 と判断
- multi-frame vision or task budget 等の architectural change が必要
- 局所 patch ではこれ以上の北進は出ない

### 終止
6 cycle (15-25) 連続で 「正しい root cause を見つけて正しい patch を入れたが
v34 best は再現できない」 trend が確定。 architectural pivot を別途検討する
