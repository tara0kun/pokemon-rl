## 3. 解決した bug / 学んだ教訓

### bug fix
1. **cache poisoning**: 同じ frame_hash で誤 action が cache 永久ループ → `useless_cache_streak >= 5` で `cache.forget()` + LocalRecovery にエスカレーション
2. **state machine 中断 (前日 v5 のもの)**: hash 変化時に `in_recovery=False + recovery.reset()` を強制 → dialog text scroll で state machine が永遠 step 0 → 削除済 (2026-06-08 b9be9aa)
3. **`UnboundLocalError: pos_changed`**: cache lookup ブロックで `pos_changed` を参照したが計算は後 → cache lookup より前に移動 (本日 v11c で修正)
4. **rescue prompt 暴走**: 同一 episode で毎 turn rescue 発火 → note 累積で token 爆発 → `rescue_fired_for` で 1 episode 1 回 only (前日修正)

### 設計判断
- **Haiku 4.5 → Opus 4.8 切替**: Haiku は安いが Vision の細かい誤読 (例「Lab を出た後も Lab 内と認識」) で agent が混乱。 Opus 4.8 だと Vision 解釈が格段に正確、 5x cost でも結果的に cheaper (loop 解消)
- **story-aware system prompt**: 単に「画面見て decide」 ではなく「Pokemon Emerald の地理と story 進行順」 を prompt に書く → Brain が 「north が Route 101 だから north に向かう」 と決められる
- **same_pos warning は明示的に書く**: 「同 pos で 5 turn 経過 + 最後 action は X → 方向 X は wall」 を user message に書くと Opus でも従う。 ただ Recent actions だけだと無視される
- **frame_hash + map_id を cache key にする**: map_id を含めることで「同じ Mom dialog でも家の中と Lab で別 action」 が可能。 また 64x64 down-sample MD5 hash で小さなアニメ frame 差にロバスト

### 教訓
- **JP ROM ではなく EN ROM**: Vision (Opus) は日本語 dialog の文脈理解が弱い → 英語 ROM で 3 マップ認識 + メモ保存が 一気に動いた (前日確認、 本日も継続効果)
- **cache の威力と限界**: 既知エリアでは 89% hit、 $0 で進める。 ただし新エリアでは Brain 必須で credit が要る
- **「prompt の細部」 が architecture と同じくらい重要**: story 知識 + STUCK warning + last_actions を入れた v11 で初めて NPC 突破。 prompt なしの v10 (同じ Opus) では同じ場所で詰まっていた

## 10. Cycle 2: tile-level collision map (根本改善 第 1 弾)

### 動機
Cycle 1 では cache invalidation + recovery escalation を試みたが、 Brain (Opus 4.8) は story 知識「Oldale=north」 で「Up」 を答え続け、 視覚的な壁を spatial に認識できなかった。 4x4 patch (positions (6-9, 7-10)) から出られず。

「Brain に spatial awareness を持たせる」 ためには、 vision 以外の signal が必要 → **明示的な tile-level collision map** を実装。

### 実装: `generic_agent/tile_map.py` (新 module)

```python
class TileMap:
    # 永続: memory/tile_map.json
    # schema: {map_id: {tiles: {x,y: {visits, tried{dir:n}, blocked[dir]}}}}
    
    def record_visit(map, x, y)          # 訪問記録
    def record_attempt(map, x, y, dir, moved)  # button 試行記録
    def summary_for(map, x, y, radius=3) → str # Brain prompt 用 summary
```

`record_attempt` で「方向 X を 3 回以上試して動かなかった」 場合に blocked リストに登録。 `summary_for` で:
- 訪問済 tile 数 (`tiles_seen=21`)
- 現在 tile の confirmed blocked direction (`blocked_here=Up,Left`)
- 半径 3 以内の unexplored frontier tile (`unexplored_nearby=[(6,7),(7,6),...]`)

### auto_loop 統合
- 毎 turn `tile_map.record_visit + record_attempt` を呼ぶ
- 毎 50 turn `tile_map.save()` で永続化
- Brain prompt に `tile_map: ...` summary 追加

### system prompt 追記 (rescue_brain.py)
```
TILE MAP — read this first:
- 'tile_map:' summary に blocked_here, unexplored_nearby
- blocked_here の方向は避けよ
- unexplored_nearby に向かう方向を優先せよ
- 'no_nearby_unexplored' なら NPC interact / door 探索
```

## 11. Cycle 3: BFS frontier rule (root-cause improvement 第 2 弾)

### 動機
Cycle 2 で tile_map に blocked direction を蓄積したが、 Brain は prompt の "unexplored_nearby" を 100% 活用しているわけではない。 また stalled → LocalRecovery の random walk は確率的。

**deterministic に未探索 frontier へ向かう algorithm が必要**:
- BFS で「現在地から最短の unexplored tile への direction」 を計算
- Brain call 不要 → free + 確実

### 実装: `TileMap.bfs_frontier_direction(map, x, y)`

```python
def bfs_frontier_direction(self, mg, mn, cx, cy) -> str | None:
    """visited tile を node、 blocked でない direction を edge として BFS。
    最寄りの unvisited tile (frontier) への first-step direction を返す。"""
    # ... BFS implementation ...
    return "Up" | "Down" | "Left" | "Right" | None
```

### auto_loop 統合
`stalled and same_map_streak >= 50` の時:
1. 先に `bfs_frontier_direction` を試す
2. 返値があれば そのまま使用 (rule.bfs_frontier として記録)
3. None なら従来の force_recovery 経由 LocalRecovery にエスカレーション

### v17 結果 (cycle 3 検証)

|------|---------------|-------------------|------|
| cost | $1.50 | $1.50 | 同等 |
| **unique positions** | 35 | **68** | **+94%** |
| maps | 3 | 3 | 同 |
| flush events | 2 (211 entries) | 2 (466 entries) | より積極 |
| **BFS rule 発火** | - | **14 回** | 新規 |

### 評価
- **同 cost で positions が 2x 倍**: BFS deterministic 探索が決定的に効いた
- BFS は 14 回しか発火しないが、 各回 「Brain が思いつかない方向」 を確実に提案
- 例: Brain が「Up (Oldale 方向)」 と言い続ける場所で BFS が「Down (frontier がある)」 を返した
- ただし Oldale Town (新マップ) への transition は未達

### 改善できた点 / 残る課題
- ✅ spatial awareness: tile_map + BFS で「未探索方向」 を deterministic に決定可能
