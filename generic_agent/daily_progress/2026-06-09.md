## 3. 解決した bug / 学んだ教訓

### bug fix
1. **cache poisoning**: 同じ frame_hash で誤 action が cache 永久ループ → `useless_cache_streak >= 5` で `cache.forget()` + LocalRecovery にエスカレーション
2. **state machine 中断 (前日 v5 のもの)**: hash 変化時に `in_recovery=False + recovery.reset()` を強制 → dialog text scroll で state machine が永遠 step 0 → 削除済 (2026-06-08 b9be9aa)
3. **`UnboundLocalError: pos_changed`**: cache lookup ブロックで `pos_changed` を参照したが計算は後 → cache lookup より前に移動 (本日 v11c で修正)
4. **rescue prompt 暴走**: 同一 episode で毎 turn rescue 発火 → note 累積で token 爆発 → `rescue_fired_for` で 1 episode 1 回 only (前日修正)

### 設計判断
- **Haiku 4.5 → Opus 4.8 切替**: Haiku は安いが Vision の細かい誤読 (例「Lab を出た後も Lab 内と認識」) で agent が混乱。 Opus 4.8 だと Vision 解釈が格段に正確、 5x cost でも結果的に cheaper (loop 解消)
- **story-aware system prompt**: 単に「画面見て decide」 ではなく「Pokemon Emerald の地理と story 進行順」 を prompt に書く → Brain が 「north が Route 101 だから north に向かう」 と決められる
- **same_pos warning は明示的に書く**: 「同 pos で 5 turn 経過 + 最後 action は X → 方向 X は wall」 を user message に書くと Opus でも従う。 ただ Recent actions だけだと無視される
- **frame_hash + map_id を cache key にする**: map_id を含めることで「同じ Mom dialog でも家の中と Lab で別 action」 が可能。 また 64x64 down-sample MD5 hash で小さなアニメ frame 差にロバスト

### 教訓
- **JP ROM ではなく EN ROM**: Vision (Opus) は日本語 dialog の文脈理解が弱い → 英語 ROM で 3 マップ認識 + メモ保存が 一気に動いた (前日確認、 本日も継続効果)
- **cache の威力と限界**: 既知エリアでは 89% hit、 $0 で進める。 ただし新エリアでは Brain 必須で credit が要る
- **「prompt の細部」 が architecture と同じくらい重要**: story 知識 + STUCK warning + last_actions を入れた v11 で初めて NPC 突破。 prompt なしの v10 (同じ Opus) では同じ場所で詰まっていた

## 9. 午後のサイクル: v12 → v15 改善実験 (cycle 1)

user 指示「区切りごとに deep に改善 → daily_progress → git」 を本日午後から開始。

### v12 (baseline、 改善前)
- $0.87 / 2500 turn / 80.9% cache hit / 40 unique positions
- map (0, 16) Route 101 で 95.3% 滞在 → 「同じ場所で Up を 500+ 回 cache hit」 という cache 強化 loop 検出

### v13 (改善 1: cache.flush_map + same_map_streak warning)
- `cache.flush_map(map_group, map_num)` 関数追加 (該当 map の cache entry 全削除)
- `MAP_STUCK_FLUSH_TURNS=800` で N turn 同 map 滞在で flush
- `same_map_streak >= 200` で prompt に「ONLY on map X for N turns、 NEW map に行け」 warning 追加
- 結果: $0.08 / 2500 turn (10x 安) / **unique 2 のみ / flush 0 件**
- bug 発見: `gs.saveblock1_valid=False` (transition state) で same_map_streak リセット → 800 到達せず

### v14 (改善 2: transition skip + stalled detector + force_navigate)
- transition state で same_map_streak を維持 (リセット禁止)
- `pos_window` (last 100 pos) で stalled = 3 tile 以下に閉じこもり 検出
- stalled なら force_navigate (cache bypass + Brain 強制 call)
- 結果: $2.43 / 2500 turn / 9 positions / **flush 2 件発火 (401 entries 削除)** / nav call 453 (高すぎ)
- 問題: Brain が「Up」 を 453 回繰り返すだけで 9 positions 微増、 cost up

### v15 (改善 3: force_navigate → force_recovery)
- stalled + same_map_streak >= 50 で `consecutive_dialog = DIALOG_LOOP_LIMIT` → LocalRecovery 強制起動
- $0 で deterministic 探索 (A×4 → B×3 → Down×2 → random×3)
- 結果: **$0.78 / 11 positions** (v14 比 cost 1/3 + 位置 +2)
- ただし agent は (6-9, 7-10) の 4x4 patch から出られず

### サイクル 1 の総括

| 指標 | v12 → v15 推移 |
|------|----------------|
| cost / 2500 turn | $0.87 → $0.78 (10% 改善) |
| unique positions | 40 → 11 (劣化、 ただし pin 留めはより堅牢) |
| nav call 抑制 | 174 → 149 (15% 改善) |
| flush 動作 | 0 → 2 (機能化) |
| 進展度 | (0,16) Route 101 で 同じ場所 |

### 根本問題 (cycle 1 で対症療法、 cycle 2 以降で本質対策)

**Brain (Opus 4.8) が画面の wall を spatial に認識できない**
- 「north に Oldale」 という story 知識を強く持つ
- 画面に trees の壁 が見えても「Up」 を答える
- 同じ患部に 100+ 回 Up → なんとなく違うtile に動くが結局戻る

### cycle 2 で検討する根本改善 (未実装)

1. **tile-level collision map**
   - 訪問済 tile を `(map_id, x, y) → button → success` で記録
   - BFS で「未訪問 frontier」 を計算
   - Brain prompt に「未訪問方向: ...」 と明示

2. **battle 検出 (RAM bridge 拡張)**
   - in_battle flag を RAM read
   - 戦闘中は別 prompt (「Fight → A」)
   - cache key にも battle state を含める

3. **multi-tile vision**
   - 1 screenshot ではなく 3-5 turn 分の screenshot を grid で Brain に渡す
   - 「最近の動き方」 を視覚的に伝える

4. **prompt の自己批判 step**
   - Brain に「直前の決定がうまく行かなかったから、 今度は何が違うか」 を考えさせる
   - cost は上がるが decision 質改善 期待
