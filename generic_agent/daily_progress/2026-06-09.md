## 3. 解決した bug / 学んだ教訓

### bug fix
1. **cache poisoning**: 同じ frame_hash で誤 action が cache 永久ループ → `useless_cache_streak >= 5` で `cache.forget()` + LocalRecovery にエスカレーション
2. **state machine 中断 (前日 v5 のもの)**: hash 変化時に `in_recovery=False + recovery.reset()` を強制 → dialog text scroll で state machine が永遠 step 0 → 削除済 (2026-06-08 b9be9aa)
3. **`UnboundLocalError: pos_changed`**: cache lookup ブロックで `pos_changed` を参照したが計算は後 → cache lookup より前に移動 (本日 v11c で修正)
4. **rescue prompt 暴走**: 同一 episode で毎 turn rescue 発火 → note 累積で token 爆発 → `rescue_fired_for` で 1 episode 1 回 only (前日修正)

### 設計判断
- **Haiku 4.5 → Opus 4.8 切替**: Haiku は安いが Vision の細かい誤読 (例「Lab を出た後も Lab 内と認識」) で agent が混乱。 Opus 4.8 だと Vision 解釈が格段に正確、 5x cost でも結果的に cheaper (loop 解消)
- **story-aware system prompt**: 単に「画面見て decide」 ではなく「Pokemon Emerald の地理と story 進行順」 を prompt に書く → Brain が 「north が Route 101 だから north に向かう」 と決められる
- **same_pos warning は明示的に書く**: 「同 pos で 5 turn 経過 + 最後 action は X → 方向 X は wall」 を user message に書くと Opus でも従う。 ただ Recent actions だけだと無視される
- **frame_hash + map_id を cache key にする**: map_id を含めることで「同じ Mom dialog でも家の中と Lab で別 action」 が可能。 また 64x64 down-sample MD5 hash で小さなアニメ frame 差にロバスト

### 教訓
- **JP ROM ではなく EN ROM**: Vision (Opus) は日本語 dialog の文脈理解が弱い → 英語 ROM で 3 マップ認識 + メモ保存が 一気に動いた (前日確認、 本日も継続効果)
- **cache の威力と限界**: 既知エリアでは 89% hit、 $0 で進める。 ただし新エリアでは Brain 必須で credit が要る
- **「prompt の細部」 が architecture と同じくらい重要**: story 知識 + STUCK warning + last_actions を入れた v11 で初めて NPC 突破。 prompt なしの v10 (同じ Opus) では同じ場所で詰まっていた
