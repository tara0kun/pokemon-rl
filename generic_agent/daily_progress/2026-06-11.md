## §22 Cycle 14: BFS hint injection + path_memory blocked filter + HARD PRIORITY prompt + cache fast eviction

### 分析手順 (multi-agent workflow)

v33 が 18 unique pos で停止した root cause を 3-finder workflow で分析:

| Finder | 角度 | 結果 |
|--------|-----|------|
| A | tile_map 解析 (Route 101 構造) | ❌ 反証: (10,0)/(11,0) は lazy-creation artifact、 東 corridor 実際は dead end |
| B | cache 解析 (key collision 仮説) | ❌ 反証: Route 101 内では fhash↔pos 1:1、 pos-keying は no-op |
| **C** | prompt + path_memory 解析 | **✓ 確定**: navigate prompt に BFS direction が無く、 path_memory が stateless で first char "U" を再生 |

### Root cause (確定)
v33 の 281 navigate call 全てが `path_memory.summary_for("0-16")` 経由で "UUURUUUD → 0-9" を見て、 prompt 指示 「first character of that sequence」 に従い **常に Up を返答**。 Route 101 北壁で Up は blocked → ping-pong 永続。 `tile_map.bfs_frontier_direction()` は計算されていたが force_recovery rule branch 内のみで、 **Brain prompt に流れていなかった**。

### 4 patches

#### Patch 1: auto_loop.py `_call_brain` に BFS hint inject
```python
if pos_now is not None and not gs.in_battle:
    bfs_first = tile_map.bfs_frontier_direction(
        gs.map_group, gs.map_num, pos_now[0], pos_now[1],
        prefer="nearest",
    )
    if bfs_first is not None and bfs_first not in cur_blocked:
        parts.append(f"bfs_to_frontier={bfs_first}")
```

#### Patch 2: path_memory.summary_for に blocked filter
```python
def summary_for(self, cur_g, cur_n, blocked_first_step=None):
    blocked = set(blocked_first_step or [])
    for tk, paths in inner.items():
        usable = [p for p in paths if p and p[0] not in blocked]
        if not usable: continue
        best = min(usable, key=len)
        pieces.append(f"to {tk} via '{seq}' first={first_full}")

```

#### Patch 3: SYSTEM_PROMPT_NAVIGATE_LONG 冒頭に HARD PRIORITY ブロック
```
HARD PRIORITY ORDER (override every other hint below):
1. If 'blocked_here' lists a direction, NEVER pick that direction.
2. If 'bfs_to_frontier=<dir>' appears AND <dir> not in blocked_here,
   you MUST pick <dir>. This was computed by BFS over the known tile
   graph; it is the verified first step toward unexplored territory
   and overrides path_memory.
3. Only if bfs_to_frontier is absent, fall back to path_memory ...
4. If neither hint applies, pick a direction toward unexplored_nearby.
```

#### Patch 4: cache fast eviction (3 turn motionless directional)
```python
if (cached and pos_now and state.last_action == cached.button
    and state.same_pos_streak >= 3
    and cached.button in {'Up','Down','Left','Right'}):

```

旧 5 turn 上限から 3 turn 短縮、 方向 button のみ (A/B は dialog で連打する正常 pattern)。

### 効果検証

## §27 Cycle 19: Phantom wall remediation (workflow-driven)

### 分析 (3 finder + 3 verifier workflow)
v40 が Route 101 を抜けない真因を多角検証:

| Finding | 結果 |
|---------|------|
| A: BFS farthest が NE 隅選択 | ❌ 反証 ((20,6) は存在しない fabricated tile、 BFS 実は Up を返す) |
| **B: tile_map 永続的 phantom wall** | ✓ 確定: (11,10) を含む 13 tile が全 4 方向 blocked = BFS 切断 |
| C: goal hint + path_memory south bias | ❌ 反証 (Up=116 で最頻、 v34 は starter_received=False でも到達) |

### root cause (確定)
`tile_map.record_attempt` が dialog/battle/recovery/menu turn でも fire → 移動失敗カウント → 3 回で blocked 化 → 永続「phantom wall」。 v40 の (0,16) では 36% の turn が dialog/recovery source → このうち direction button = 偽 stall として記録。 tile (11, 10) が x=11 corridor の唯一の入口だったが 4-way 全 sealed → BFS が「北無理」 と判定。

### 実装 (tile_map.py + auto_loop.py + path_memory.py)
1. `record_attempt(overworld=True)` kwarg 追加。 auto_loop が `not in_battle and consecutive_dialog == 0 and not in_recovery and same_hash_streak < 3` を pass → False なら短絡 return
2. **Hard 4-way seal guard**: 4 つ目の direction を blocked に追加する瞬間に reset tried/blocked + warn print (standing tile が 4 方向 blocked は構造上不可能)
3. `tile_map.decay(map_g, map_n)`: 50 turn 毎 fire、 blocked 3 個以上の tile から 1 個 pop + tried zero (1 個 tile/run の再試行猶予)
4. `tile_map.cleanup_phantom_walls()`: startup で全 map の 4-way blocked tile を全 clear
5. **path_memory.summary_for(avoid_first=set)**: suppress_dir を渡し、 該当 first step の path を hide。 「Down に行くな」 期間中 `to 0-10 first=Down` を抑制

### v41 結果
- **82 pos / 3 maps / $1.50**
- startup で 13 phantom walls cleared ((11, 10) ふくむ)
- 4-way refused: 0 件 (overworld gate 動作 → 新規 phantom 発生なし)
- decay 2 件 fire
- **だが Oldale 未到達**: A 押下 49.5% で dialog/sign 関連が turn の半分を消費している事実発覚
