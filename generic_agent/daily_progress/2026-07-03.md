## Fix 1: LEDGE_JUMP_BEHAVIORS off-by-one (commit 8d097e15c)

### 症状
agent が Woods (16,31) で 461 turn stuck。heur は `Up mapbfs:Up->PetalburgWoods` を
出し続けるが (16,30) は walkable=False の壁で一歩も動けない。

### 真因 (3 証拠)
1. **コード**: `LEDGE_JUMP_BEHAVIORS` が `0x39:EAST .. 0x40:SW` — canon
   (`metatile_behaviors.h` enum: `MB_UNUSED_2C-2F`=0x2C-2F → `MB_IMPASSABLE_*`=0x30-37
   → `MB_JUMP_EAST`=**0x38** .. `MB_JUMP_SOUTHWEST`=**0x3F**) より **全 ID +1 ズレ**
2. **実データ**: Woods y30 の ledge 帯 (16-21,30) は behavior **0x3B = JUMP_SOUTH**
   (南向き飛び降り専用)。コードはこれを JUMP_NORTH=(0,-1) と誤読
3. **症状一致**: BFS が「南 ledge を Up で登れる」と誤判定 → 物理的に不可能な Up を
   出し続けて stuck

### 修正
- テーブルを 0x38-0x3F に是正
- キャッシュ済み map_knowledge JSON 6 file の ledge_jumps を canon から再計算
  (0-17 は取りこぼしていた EAST ledge 4 個も回復)
- 修正後 BFS: 26 歩の不正経路 → **81 歩の実走可能な西回廊迂回路**
- explore_target hijack guard を peeko/rescue_peeko goal にも拡張

# Track B — Claude + SakanaAI/Codex dual_dev hardening

## TL;DR

- VSCode上で Claude Code を設計/レビュー、SakanaAI/Codex を実装担当にする `generic_agent/dual_dev/` 運用を実装・安全化。
- デフォルトは dry-run。commit は `--commit` 指定時のみ、deterministic gates と Claude review が両方 PASS の場合だけ実行。
- 既存の dirty / untracked 作業を誤って上書きしないため、dirty path の prefix conflict 検出を追加。
- usage limit / timeout / CLI未起動でも orchestrator 自体が落ちず、run state に残して resume できるようにした。

## 実装

- `generic_agent/AI_COLLABORATION.md`: Claude と SakanaAI/Codex の役割分担、制約、handoff形式を定義。
- `generic_agent/dual_dev/`: semi-autonomous development loop を追加。
  - `orchestrate.py`: Claude design → Codex implementation → gates → Claude review の cycle runner。
  - `gates.py`: allow-path、dirty conflict、禁止API、diff size、Python compile の deterministic gates。
  - `clients.py`: Claude/Codex CLI subprocess wrapper。
  - `config.py`: executable discovery、timeout、directory設定。
