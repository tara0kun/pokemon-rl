## §17 Cycle 9: path_memory.py (transition memory)

### 動機
v22-v24 で variance が大きく、 v21 (95 pos) を再現できない。 cache に「成功した path」 が学習されない → 毎 run ゼロから探索。

### 実装
新規モジュール `generic_agent/path_memory.py`:
- 構造: `{from_map: {to_map: [button_seq1, button_seq2, ...]}}`
- map_id 変化時 (= map transition) に最近 8 action を記録
- summary_for(map) → Brain prompt の "known exits: to 3-0 via UUUa" hint

### v29 結果
- 53 pos / 4 maps / $1.10
- LONG prompt 復帰 (cycle 10 の simplified を revert) + Opus + no thinking
- Brain が path_memory hint を活用、 Route 101 まで到達
- **Route 101 (0,16) で 1287 turn stuck** ← 新マップ stuck 問題が露呈

### 教訓
- path_memory は「button 列」 のみ記録、 「どの tile から開始すべきか」 が無い
- 同 sequence を別 tile で再生 → 失敗の繰り返し
- これが cycle 13 の cache key bug 発見の伏線

## §21 Cycle 13: Cache lookup の blocked_here validation

### 真の root cause 発覚

`local_brain.FrameCache.lookup` の key:
```python
def _key(self, fhash, map_group, map_num):
    return (fhash, map_group, map_num)   # pos (x, y) を含まない
```

→ Map (0, 9) 内の **異なる tile で類似画面 が同じ cache key を共有**
→ 「(10, 2) で Up が成功」 が cache → (5, 2) でも Up 返す → tile_map では (5, 2) Up blocked → wasted

`useless_cache_streak >= 5` でようやく eviction、 5 turn 無駄遣い。 v32 で navigate 248 回中、 多数がこの cache 誤射の後始末。

### 修正
`auto_loop.py` の cache lookup 前に整合性 check:

```python
cache_blocked_here = False
if cached and pos_now is not None:
    rec_cur = tile_map._store.get(mk_cur, {}).get(tile_map._tile_key(*pos_now))
    if rec_cur is not None and cached.button in rec_cur.blocked:
        cache_blocked_here = True
        cache.forget(fhash, gs.map_group, gs.map_num)
```

cache に「現 tile で blocked のはずの button」 が入っていたら即廃棄。 1 turn も無駄にしない。
