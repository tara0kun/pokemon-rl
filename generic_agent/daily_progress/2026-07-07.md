## nav: gym leader への到達を根治(H6b の nav 側)

**症状**: H1 修正後、agent は Gym 迷路に入れるが Brawly (4,3) 手前で toward_exit に落ちて
(4,25) で停滞。BFS は (4,25)→(4,3) を 38歩で解けるのに mapbfs が発火しない。

**真因(decide() 再現で確定)**: 前 run が Brawly に face+A で bump した際、移動失敗が tile_map に
「blocked」記録され、Brawly の唯一の歩行可能接近タイル **(4,4)/(3,3) が empirical_blocked に
入り、BFS が None → toward_exit → 壁に Up 連打 → stuck**。

**修正 (claude_heuristic.py)**:
- goal target_pos を**常に interact_target 化**し、歩行可能な隣接タイルを target に(gym leader は
  face+A で talk、grass tile は踏む、両対応)。walk-onto 決め打ちを廃止(leader は read 圏外で
  NPC 判定されず、その own タイルを目指して永遠に bump していた)。
- bfs_blocked から **interact 対象 + 接近ゾーンを免除**(bump 由来の tile_map 汚染を壁扱いしない)。
- 到達タイル == 対象自身なら face+A をスキップ(grass から歩き去るのを防止)。

**検証 (live)**: 迷路を mapbfs で単調に突破((4,25) 停滞なし)→ (4,4) で `npc_interact:Up→A` →
