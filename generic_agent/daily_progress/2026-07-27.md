### 2. party_count RAM バグ 根治 (commit f2ccef9de)
- **症状**: 捕獲成功なのに `state.read_state().party_count` が **5/0 で flicker**、真値 6 を返さない。
- **実測で真因**: mons(level/hp/species)は live global `gPlayerParty`(0x020244EC)から読むのに、
  **count だけ SaveBlock1 mirror(`ptr+0x234`)** から読んでいた。SaveBlock1 mirror は **save 時のみ
  同期** → catch 後 save までずっと stale(前回 save 時の 5)。0 は SaveBlock1-ptr の DMA frame。
  - 測定: `gPlayerPartyCount@0x020244E9 = 6`(安定、11/12、隣接 E8/EA/EB=0、personality count=6 と一致)、
    `SB1+0x234 = 5`(stale)、save 後 mirror も 6 に同期。
- **修正**: count も live global(`PLAYER_PARTY_ADDR-3 = 0x020244E9`、fixed BSS = DMA 非再配置)から
  読む1行変更。loop は `party_count` を `saveblock1_valid` frame でのみ意思決定に使う(grep 確認)ので
  invalid-frame の 0 は inert。
- **verifier CONFIRMED**(read-only RAM 再現 + 293 tests)。GOTCHAS + memory
  [[saveblock1-mirror-is-save-lagged]] 記録。
