## プロセス教訓

- **loop 起動は harness run_in_background(TaskStop)を使う。`nohup ... &`＋`kill $!` は
  Windows Git Bash で detached python を殺さず、restart 2 回で 4 重起動→socket 奪い合いで
  agent erratic 化**（memory current_project.md に追記済）。venv python は shim+実体で
  1 invocation=2 プロセス。
- mid-loop RAM read は socket 競合で壊れる → 必ず loop 停止後に read（memory 既知）。
- per-turn decision trace は `logs/decisions_<session>.jsonl` に無条件記録。src 分布 +
  goal 分布で chronic stuck を分解できる（今回の真因特定はこれ）。
