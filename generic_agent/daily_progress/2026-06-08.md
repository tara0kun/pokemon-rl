# 2026-06-08 — プロジェクト方針の大転換 + 新アーキテクチャ実装

## 1. 今日の最重要決定 (project pivot)

### 旧アプローチ
- `pokemon_env.py` (~23,000 行) のルールベース攻略 AI
- BFS pathfinding + ハードコード script trigger
- patches #1〜#28 (15+ patches in 2 weeks) で patch-tower 化
- 「汎用 AI」 と謳いつつ実態は Emerald 専用 bot

### 新アプローチ (今日決定)
- **VLM (Vision Language Model) Agent**: Claude が screenshot を見て判断
- Anthropic 公式の Claude Plays Pokemon が Red をクリア済 = 実証済 path
- ROM 切替だけで他 Pokemon シリーズに転用可能 (本来の「汎用」 を実現)
- ハードコード一切なし → patch-tower 連鎖崩壊が原理的に起きない

### user 4 つの constraint (今日合意)
1. **モデル**: Claude (`claude-opus-4-8` 第一候補)
2. **干渉防止**: 別 VSCode プロジェクトとぶつからない (port 8895、 ROM コピー)
3. **既存資産**: 残しておいて使えたら使う (rule-based コードは legacy/ へ)
4. **データ信用度**: exploration_map.json 等は参考程度、 信用しすぎない

### emulator 操作
- mGBA を Claude が完全自律制御するのは技術的に不可 (CLI に --script flag なし)
- 妥協案 (選択肢 3): **mGBA 起動と lua load のみ user 手動 (1 回)**、 以降 100% Claude 操作
- 既存 training も実は同じ手動起動だったので、 実質変化なし

## 2. 実装した architecture

### Week 0 (環境セットアップ)
- `generic_agent/` ディレクトリ新設
- mGBA-http socket 直叩き (既存 lua script を port 8895 に編集してコピー)
- ROM コピー (`emerald_en.gba` / `emerald.gba`)
- mGBA に対しては毎 turn screenshot + RAM read + button send で完結

### Week 1 v1 (初期 Brain LLM ループ)
- `brain.py`: Opus 4.8 + tool use (`press_buttons`/`wait`/`record_observation`)
- `loop.py`: 1 turn = screenshot → Brain call → action 実行
- `memory.py`: notes (JSONL) + run_log (JSONL) 永続化
- `prompts.py`: system prompt (mechanics + memory discipline)
- `state.py`: SaveBlock1 経由で map/pos/saveblock1_valid を RAM read

### Week 1 v2 (高度化)
- `stuck detection`: rolling hash 8 turn window で同一 hash 3+ なら stuck flag
- `long-stuck rescue prompt`: same_map_streak >= 30 で「(a) 何を試したか (b) なぜ駄目か (c) 別アプローチ」 を強制 record_observation
  - ⚠️ 暴走 bug 検出: 「1 episode 1 回」 を実装 (rescue_fired_for による gating)

### Week 1 v3 (英語 ROM + RAM bridge 統合)
- 英語 ROM (`Pokemon Emerald (USA, Europe).gba`) に切替
- 効果: **JP 比 dramatic 改善** (3 map 認識 + 3 notes 保存 + ママ会話到達)

### 最終 architecture (cost-optimized、 今日夜実装)
- **3 段 decision flow** (per turn):
  1. `FrameCache` lookup (永続 JSON、 `(frame_hash, map_id)` キー) → hit なら $0 で reuse
  2. `default_rule_for_state`: pos unchanged + last_action=A → 「dialog 継続」 と判断、 A 押し
  3. なし → `call_navigate` (Haiku 4.5 + JPG + JSON-strict、 $0.001/call)、 結果を cache 保存
  4. 画面 frozen 3 turn → `LocalRecovery` (B連打 → A → random walk、 全 $0)
  5. 画面 frozen 8 turn → `call_rescue` (Haiku、 max_tokens=120)
- **cost target**: $0.005/turn → $0.0001-0.0005/turn (**90-95% カット**)

## 4. 解決した bug / 学んだ教訓

### bug
- **A 連打バグ**: `default_rule_for_state` で same_hash_streak ≤ 2 = A 強制 → 全 turn A 化。 修正: pos unchanged + last_action=A の組合せで初めて発火
- **rescue prompt 暴走**: 同一 episode 内で毎 turn rescue 発火 → note 累積で token 肥大。 修正: rescue_fired_for で 1 episode 1 回 only
- **RAM read 空文字列 crash**: lua からの empty response で `int("")` が ValueError。 修正: `_parse_int` helper で全 read 系統 robust 化
- **mGBA lua script 多重 load**: ROM 切替時にリロードで 4 listener 重複 → message router 混乱。 復旧: mGBA 一旦閉じて 1 instance 再起動

### 教訓
- **JP ROM の Vision 理解は弱い**: 同じ Opus 4.8 でも英語 dialog の方が圧倒的に文脈理解できる → ROM 言語選択は cost より重要
- **OAuth login (`ant auth login`) は credit 問題を解決しない**: subscription quota と API billing は完全分離 (Anthropic 公式設計)
- **VSCode Extension の claude.exe は subscription quota を使う が 1 call ≈ $0.15 相当**: Pro/Max でも長時間連用は危険
- **patches-tower 連鎖崩壊は LLM agent でも形態が違うだけで発生**: prompt 過剰追加で token 肥大 → 同じ罠 → 「1 episode 1 回」 原則の重要性
- **rule-based + LLM のハイブリッドが最適**: 全部 LLM は高コスト、 全部 rule は柔軟性不足
